## Overview

The `Conversation` class stores and manages message history for agents and multi-agent workflows. You can add and edit messages, search history, persist conversations as JSON or YAML, track tokens, compact old interactions into a summary, and format history for downstream consumers.

The class keeps conversation state in memory while the process is running. Persistence is optional and controlled through `autosave`, `save_filepath`, `load_filepath`, `conversations_dir`, and `export_method`.

## Installation

```bash
pip install -U swarms
```

## Import

```python
from swarms.structs import Conversation
```

The current constructor accepts the following arguments:

```python

    save_filepath: Optional[str] = None,
    load_filepath: Optional[str] = None,
    context_length: int = 8192,
    rules: Optional[str] = None,
    custom_rules_prompt: Optional[str] = None,

    save_as_yaml_on: bool = False,
    save_as_json_bool: bool = False,
    token_count: bool = False,
    message_id_on: bool = False,
    tokenizer_model_name: str = "gpt-5.4",
    conversations_dir: Optional[str] = None,
    export_method: str = "json",
    dynamic_context_window: bool = True,
    cache_enabled: bool = False,
    output_metadata: bool = False,
    memory_md_path: Optional[str] = None,

```

## Initialization and persistence

An unnamed conversation receives a new generated name and starts fresh. If you provide an explicit name or persistence path, the class can resume matching saved state when it exists.

`export_method` controls whether `export()` writes JSON or YAML and also controls the expected extension of `save_filepath`. The current JSON and YAML save methods serialize the conversation history itself. The corresponding loaders accept that history-list shape and also retain compatibility with the older wrapped metadata shape.

<Note>
Use an explicit `name` or path when you want predictable persistence. Leave both unset when you want an independent conversation with a generated identity.
</Note>

## Methods

### `add()`

Add one message and return the stored message dictionary.

```python
def add(
    self,
    role: str,
    content: Union[str, dict, list, Any],
    metadata: Optional[dict] = None,
    category: Optional[str] = None,
)
```

When enabled, the method also adds timestamps, message IDs, token counts, `MEMORY.md` entries, and autosave behavior.

### `add_messages()`

Add standard chat-format messages in order.

```python
conversation.add_messages(
    [
        {"role": "user", "content": "Summarize this."},
        {
            "role": "assistant",
            "content": "Sure.",
            "tool_calls": [{"id": "call-1"}],
        },
    ]
)
```

Keys other than `role` and `content`, such as `name`, `tool_calls`, or `tool_call_id`, are retained as metadata.

### `add_multiple()` and `add_multiple_messages()`

Add parallel role/content lists in their original order. The two lists must have equal lengths.

```python
conversation.add_multiple(
    roles=["user", "assistant"],
    contents=["Hello", "Hi"],
)
```

### `return_history_as_string()`

Return the conversation as a formatted string. When `dynamic_context_window=True`, the returned string is reduced to fit `context_length`. When caching is enabled, repeated reads reuse the cached value until the history changes.

```python
history = conversation.return_history_as_string()
```

### `compact()`

Replace interaction history with a summary while preserving static context in this order:

1. `system_prompt`
2. `rules`
3. `custom_rules_prompt`
4. the new summary message

If `memory_md_path` is configured, the previous memory log is archived before the active log is re-created.

```python
conversation.compact(
    summary="The user asked about X. The assistant explained X.",
    summary_role="System",
)
```

### `export()`

Persist the conversation using `export_method`.

```python
conversation.export_method = "json"
conversation.export()
```

Pass `force=False` if you want the save operation to respect the `autosave` setting.

### `load()`

Load JSON, YAML, or YML history from an explicit file.

```python
conversation.load("conversation.json")
```

The loader logs a warning and returns when the path does not exist. Unsupported extensions raise `ValueError`.

### `search()`

Search message contents for a keyword.

```python
results = conversation.search("weather")
```

`search_keyword_in_conversation()` is also available for the same kind of history lookup.

### `truncate_memory_with_tokenizer()`

Mutate `conversation_history` so it fits the configured token budget. Complete messages are kept until the next message would exceed the limit; that final message can be truncated to fit the remaining budget.

### `dynamic_auto_chunking()`

Return a history string that fits within `context_length` without mutating `conversation_history`. This is the path used by `return_history_as_string()` when `dynamic_context_window=True`.

### `export_and_count_categories()`

Count tokens for messages categorized as `"input"` and `"output"`.

```python
tokens = conversation.export_and_count_categories()
print(tokens["input_tokens"])
print(tokens["output_tokens"])
print(tokens["total_tokens"])
```

If counting fails, the method returns zero for all three counts.

### Message editing and lookup

| Method | Behavior |
| --- | --- |
| `query(index)` | Return the message at `index`, or `None` when the index is outside the history |
| `delete(index)` | Remove the message at `index` |
| `update(index, role, content)` | Replace a message's role and content |
| `search(keyword)` | Return messages whose stringified content contains `keyword` |
| `batch_add(messages)` | Extend history directly with a list of message dictionaries |
| `clear()` | Empty the conversation history |
| `count_messages_by_role()` | Return message counts grouped by role |
| `add_tool_output_to_agent(role, tool_output)` | Add a tool-output dictionary through the normal `add()` path |

### Output helpers

| Method | Return value |
| --- | --- |
| `get_str()` | Alias for `return_history_as_string()` |
| `get_cache_stats()` | `hits`, `misses`, `cached_tokens`, and `hit_rate` |
| `get_last_message_as_string()` | Final message formatted as `"role: content"`, or an empty string |
| `get_final_message()` | Final message formatted as `"role: content"`, or an empty string |
| `get_final_message_content()` | Content of the final message, or an empty string |
| `return_messages_as_list()` | List of `{"role", "content"}` dictionaries |
| `return_messages_as_dictionary()` | Alias for the role/content dictionary list |
| `return_messages_as_strings()` | List of `"role: content"` strings |
| `return_json()` | Pretty-printed JSON for the role/content dictionary list |
| `to_dict()` | The underlying conversation-history list |
| `to_json()` | JSON string of the underlying history |
| `to_yaml()` | YAML string of the underlying history |
| `to_list()` | The underlying conversation-history list |

### History slices

`return_all_except_first()` and `return_all_except_first_string()` return the interaction output after the initial input. When history begins with a system message, both the system message and first input are skipped. When no system message exists, only the first input is skipped.

This distinction matters for agent histories such as `[System, User, ...]` and workflow histories such as `[User, agent, agent, ...]`.

### Saved-conversation helpers

| Method | Behavior |
| --- | --- |
| `Conversation.load_conversation(name, conversations_dir=None, load_filepath=None)` | Load from an explicit path or search for a named JSON/YAML conversation |
| `Conversation.list_conversations(conversations_dir=None)` | Return metadata for compatible saved JSON conversations |
| `Conversation.list_cached_conversations(conversations_dir=None)` | Return sorted names for JSON/YAML files in the conversation directory |
| `export_conversation(filename)` | Export JSON when the filename ends in `.json`; otherwise write simple `role: content` text |
| `import_conversation(filename)` | Import JSON history |

### `get_visible_messages()`

For histories that include turn and visibility metadata, return messages from earlier turns that are visible to a specific agent.

```python
visible = conversation.get_visible_messages(agent=agent, turn=3)
```

This is an advanced multi-agent helper. Each inspected message is expected to contain `turn` and `visible_to` fields.

## Usage examples

### Basic conversation

```python
from swarms.structs import Conversation

conversation = Conversation(
    name="my-conversation",
    system_prompt="You are a helpful assistant.",
    time_enabled=True,
    token_count=True,
    context_length=8192,
)

conversation.add("user", "Hello, how are you?")
conversation.add("assistant", "I am doing well, thanks.")
conversation.add("user", "What is the weather in Tokyo?")

print(conversation.return_history_as_string())
```

### Start with existing messages

```python
conversation = Conversation(
    messages=[
        {"role": "user", "content": "Compare JSON and YAML."},
        {"role": "assistant", "content": "Both are serialization formats."},
    ]
)

print(conversation.return_messages_as_list())
```

### Export and load

```python
conversation.export_method = "json"
conversation.export()

conversation = Conversation.load_conversation(
    name="my-conversation",
    load_filepath="conversation_my-conversation.json",
)
```

### Token tracking

```python
conversation = Conversation(
    token_count=True,
    context_length=4096,
    dynamic_context_window=True,
)

conversation.add("user", "My input", category="input")
conversation.add("assistant", "My response", category="output")

tokens = conversation.export_and_count_categories()
print(f"Input tokens: {tokens['input_tokens']}")
print(f"Output tokens: {tokens['output_tokens']}")
print(f"Total tokens: {tokens['total_tokens']}")
```

### Search and query

```python
results = conversation.search("weather")
last_message = conversation.get_last_message_as_string()
message = conversation.query(0)
```

## Features

- **In-memory history:** Keep ordered messages for agents and workflows.
- **Structured message metadata:** Add timestamps, IDs, categories, token counts, and custom metadata.
- **Persistence:** Save and restore JSON or YAML history.
- **Persistent memory:** Mirror interactions to `MEMORY.md` and archive it during compaction.
- **Token management:** Count tokens, truncate history, and dynamically limit formatted context.
- **Caching:** Reuse formatted history until a mutation invalidates the cache.
- **Search and editing:** Search, query, update, delete, batch-add, and clear messages.
- **Multiple output formats:** Produce strings, lists, dictionaries, JSON, and YAML.
